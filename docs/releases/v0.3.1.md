Tessera 0.3.1 is a small fix release. It corrects how hard-linked files are counted in the live updates after a scan.

## Fixes

A file can have several names (hard links), for example in the Windows component store (WinSxS), or when pnpm links packages into each project's `node_modules`. The scan already counted such a file only once, but the live tracking of changes after the scan did not keep that up:

- Creating a new hard link counted the file's size again, so the total came out too high.
- Deleting the name the size was counted under made the size disappear from the map, while the other names still showed 0.
- Changing the file through another of its names did not update the size shown.
- In folders that appeared or were rescanned after the scan, a file that also had a name elsewhere was counted twice.
- When running as administrator, new hard links did not appear in the map, and deleted ones stayed in it.

Now, however its names are created, renamed or deleted, each file's size is counted once, and when one of its names is deleted the size moves to a remaining name. This tracking only applies to local NTFS drives; other file systems are not affected.
